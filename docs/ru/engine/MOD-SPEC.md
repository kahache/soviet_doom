# MOD-SPEC — технический контракт мода

Владелец: `mod-engineer`. Контракт с `level-designer` и `art-director`: имена,
пути и лампы, которые ожидает движок. **Изменить его = обновить этот документ
раньше кода.** Статус: арсенал F4 проверен на GZDoom 4.14.2, 2026-10-12;
патроны переименованы, а взмах лопаты сделан беззвучным после игровой
сессии CEO, 2026-10-13 (пайплайн F0 проверен 2026-10-09).
Английский оригинал: `docs/engine/MOD-SPEC.md`.

Минимальный глоссарий (для новичков в моддинге Doom):

- **IWAD**: файл данных базовой игры (`doom2.wad` или `freedoom2.wad`). Без него
  GZDoom не запускается.
- **PK3**: `.zip` с фиксированной структурой папок, который GZDoom монтирует
  поверх IWAD. Формат мода.
- **Ламп (lump)**: именованный блок данных (не более 8 символов ASCII). В PK3
  каждый файл — ламп, названный по имени файла без расширения.
- **UDMF**: текстовый формат карты (`TEXTMAP`), используемый GZDoom; мы
  генерируем его из Python.
- **DoomEdNum**: число, которым редактор карт обозначает размещаемый объект;
  `1` — «Player 1 start».

## 1. Идентичность

| Поле | Значение | Примечание |
|---|---|---|
| Название мода | **Soviet Doom**, пакет `sovietdoom` | D1 (ждёт ратификации CEO) |
| Префикс | `SD` / `SD_` | классы ZScript, идентификаторы LANGUAGE, собственные лампы |
| Выходной файл | `dist/sovietdoom.pk3` | генерируется `tools/build.py`; никогда не правится вручную |
| Движок | GZDoom 4.14.2, `version "4.12"` в `zscript.txt` | D3 (ждёт ратификации) |
| Поддерживаемые IWAD | `freedoom2.wad` (предпочтительно, D2) и `doom2.wad` | см. §5 |

## 2. Структура PK3 (выход)

```
sovietdoom.pk3
├── MAPINFO                 карты, эпизоды, GameInfo (AddEventHandlers)
├── LANGUAGE                локализованный текст: [enu default] и [ru] (D7)
├── SNDINFO                 логическое имя звука -> ламп (F4)
├── zscript.txt             вход ZScript: version + #include
├── zscript/sd/*.zs         системы (обработчики событий, класс игрока, патроны)
├── zscript/weapons/*.zs    арсенал, один класс на файл (F4)
├── maps/MAP01.wad          один WAD на карту, лампы MAP01, TEXTMAP, ENDMAP
├── maps/MAP02.wad          инженерный тестовый полигон (F4)
├── textures/  flats/       собственные текстуры стен и флэты
├── sprites/  sounds/  music/  graphics/  patches/  hires/
├── (долг T9) fonts/defsmallfont/<HEX>.png   кириллические глифы для SmallFont
└── (будущее) ANIMDEFS, TEXTURES, GLDEFS, CVARINFO в корне
```

Правила:
- Файлы в корне: имя ≤ 8 символов без расширения (сборка проверяет и падает иначе).
- Лампы карт: `MAP01`, `MAP02`, … (формат Doom II). Внутри WAD порядок
  фиксирован: маркер `MAPxx` (пустой), `TEXTMAP`, `ENDMAP` (пустой). Без лампов
  нод: GZDoom строит их при загрузке (проверено на G0).
- Карты не распаковываются: GZDoom читает `maps/MAP01.wad` напрямую.

## 3. Структура `src/` (вход сборки)

```
src/
├── lumps/        → корень PK3 (плоско)
├── zscript/      → zscript/  (копируется как есть; sd/ = системы, weapons/ = арсенал)
├── maps/MAP01/map.py   → maps/MAP01.wad  (генерируется; определяет lumps())
├── maps/MAPxx.wad      → maps/MAPxx.wad  (копируется как есть; выход UDB)
└── textures/ flats/ sprites/ sounds/ music/ graphics/ patches/ hires/ → те же пути
```

- Генерируемая карта (`map.py`) предоставляет `lumps() -> list[(name, bytes)]`,
  первый ламп — маркер с именем папки. Импортирует `sdbuild.udmf` для сборки
  `TEXTMAP` (`tools/sdbuild/udmf.py`).
- `level-designer` может сдать `.wad`, сделанный в Ultimate Doom Builder, в
  `src/maps/`; сборка упаковывает его без изменений. Имя файла = имя карты.
- Сборка детерминирована (фиксированные метки времени, отсортированные записи):
  одни и те же исходники дают идентичные байты (есть тест).

## 4. Карты

| Ламп | Заголовок (LANGUAGE) | Эпизод | Статус |
|---|---|---|---|
| `MAP01` | `SD_MAP01_NAME` = "Zarya-7 Cosmodrome" / «Космодром "Заря-7"» | `SD_EP01_NAME` = "Soviet Doom" / «Советский Doom» | Владелец — `level-designer`, начиная с F3; дизайн в `docs/levels/MAP01-zarya-7.md`. `cluster = 1`, `next = endtitle`, `par = 210`. Названа в движке 2026-10-13 (лог выводит `MAP01 - Zarya-7 Cosmodrome`). |
| `MAP02` | `SD_MAP02_NAME` = "Engineering Test Range" / «Инженерный полигон» | нет (вне эпизода) | F4: зал 2048×768, потолок 128, свет 192, старт игрока в (160,384) лицом к +x. Семь видов оружия, четыре пула патронов, бочки и цели-плейсхолдеры. Запускается командой `MAP=MAP02 tools/run.sh`. Инженерная заготовка, **не артефакт дизайна**. |

Соглашения MAPINFO: `clearepisodes` + один эпизод на кампанию; заголовки карт
через `lookup`, заголовок эпизода через `name = "$ID"` (**`lookup` не
принимается внутри блока episode**, проверено, B1); `music = ""`, пока нет
музыки (проверено: тишина, без предупреждения); `sky1 = "SKY1"`.

### 4.1 Как заканчивается кампания (M3, закрыт 2026-10-13)

`Exit_Normal` на MAP01 завершает игру. Три факта, все проверены в движке,
нужны каждому, кто тронет это место:

- **Текст конца эпизода принадлежит КЛАСТЕРУ, а не карте.** Очевидное
  `next = EndGame { Text = "…" }` не парсится: блок endgame принимает
  только `pic`, `hscroll`, `vscroll`, `cast` и `music`
  (`ParseEndGame`, `src/intermission/intermission_parse.cpp`), и GZDoom
  отвечает `Unknown property 'Text' found in endgame definition`. Нужная
  запись — `cluster 1 { exittext = lookup, "SD_END01_TEXT" flat =
  "SDFLR1" }`.
- **`next = endtitle`** — именованная концевая последовательность для
  «проиграть финал, затем вернуться на титульный экран» (`CheckEndSequence`,
  тот же файл).
- **`nointermission` убран из MAP01.** Раньше нажатие на выход бесшумно
  перезапускало карту; экран статистики теперь впервые сообщает, что
  уровень пройден. `par = 210` — цифра `level-designer`. **НЕ ПРОВЕРЕНО**:
  что экран выводит 3:30 — строка PAR появляется, но её значение
  анимируется вверх и не стабилизировалось за время автоматического
  прогона без участия человека. QA, с человеком за клавиатурой.

### 4.2 Используемые спешлы карты (M5, из §9 `level-designer`)

ЧИСЛА line-special ZDoom вкомпилированы в движок, а не поставляются в
каком-либо файле, поэтому их проверили единственным оставшимся способом:
прошли карту в v0 и посмотрели, как движется геометрия. Доказательства — в
`docs/levels/shots/`. *Формы* аргументов всё же поставляются, в
`gzdoom.pk3 → xlat/`.

| Спешл | № | Аргументы | Для чего используется | Статус |
|---|---|---|---|---|
| `Door_Raise` | **12** | `(tag, speed, delay, lighttag)`, задан как `(tag, 16, 150, 0)` | ручная дверь, открываемая с обеих сторон; `playeruse` + `repeatspecial` | **ПРОВЕРЕНО в движке** 2026-10-13 |
| `Door_Open` | **11** | `(tag, speed, lighttag)`, задан как `(tag, 16, 0)` | нажимная панель, которая остаётся открытой, и односторонний настенный выключатель, открывающий удалённую дверь по тегу | **ПРОВЕРЕНО в движке** 2026-10-13 |
| `Exit_Normal` | **243** | `(pos)` | выключатель выхода с уровня | **ПРОВЕРЕНО в движке** 2026-10-13; с этого изменения завершает игру (§4.1), а не перезагружает MAP01 |

Константы из `xlat/defines.i`: `D_SLOW = 16`, `VDOORWAIT = 150`. Теги —
это UDMF `id` на секторе и `arg0` на линии.

Два факта о движке, каждый стоивший `level-designer` одной пересборки,
записаны здесь, чтобы следующий человек не платил снова:

- Спешл `playeruse` срабатывает **только с лицевой стороны линии**, так
  что двери нужен спешл на *обеих* обрамляющих линиях, каждая из которых
  обращена к двери своей ЗАДНЕЙ стороной. `LineStyle.back_sector` в
  `tools/sdbuild/udmf.py` делает это, а `tests/test_udmf.py` это
  проверяет.
- `Door_Raise` / `Door_Open` поднимают дверь до **(потолок ближайшего
  соседа − 4)**, так что дверь, открытая со стороны низкого соседа, может
  оказаться непроходимой.

Пока не проверено и поэтому не является контрактом: `Light_ChangeToValue`
(110), `Light_Flicker` (113), сектор `special = 1024` (секрет). v2.

## 5. Используемые ассеты IWAD

Мод не распространяет ничего из IWAD. Freedoom сохраняет имена лампов Doom II,
поэтому ссылка по имени работает на обоих. Каждая ссылка на IWAD должна быть
здесь и в индексе текстур `art-director` с пометкой «IWAD».

| Имя | Тип | Где используется | Проверка |
|---|---|---|---|
| `STARTAN2` | текстура стены 64×128 | MAP01, 4 стены | проверено на freedoom2.wad 0.13.0 (скриншот G0) |
| `FLOOR4_8` | флэт (пол) | MAP01 | проверено |
| `CEIL3_5` | флэт (потолок) | MAP01 | проверено |
| `SKY1` | текстура неба | MAPINFO `sky1` | загружается без ошибок |

Неявно используемые элементы IWAD: HUD и строка статуса, четыре пула
патронов (`Clip`, `Shell`, `RocketAmmo`, `Cell`) с их подборами и классы
оружия Doom, от которых наследуется арсенал. Начиная с F4 пешка игрока и все
семь видов оружия — **наши** (§6); оружие Freedoom заменено, а
супердробовик и кулак нельзя разместить на карте.

`MAP02` дополнительно размещает акторов Freedoom как **тестовые
заготовки**: взрывающуюся бочку (2035), зомби (3004), аптечку (2012), синюю
броню (2019), рюкзак (8) и ящики патронов 2046/2048/2049/17. Это
плейсхолдеры до появления бестиария (F5), и ни на одной карте кампании они
не встречаются.

## 6. ZScript

- Вход: `zscript.txt` с `version "4.12"` и только `#include`.
- Один класс на файл. `zscript/sd/` содержит системы, `zscript/weapons/` —
  арсенал. Имена классов с префиксом `SD_`.
- Обработчики событий регистрируются в `MAPINFO → GameInfo → AddEventHandlers`.
- Класс игрока объявляется в `MAPINFO → GameInfo → PlayerClasses`
  (пешка игрока не может использовать `replaces`).
- Каждое игровое число — именованная константа, в комментарии к которой
  написано, почему оно такое; обоснование живёт в `docs/engine/BALANCE.md`.

| Класс | Тип | Назначение |
|---|---|---|
| `SD_LoadReporter` | `EventHandler` | `WorldLoaded` → `Console.Printf("SOVIETDOOM loaded: …")`. Дымовой тест пайплайна. Не влияет на игру. |
| `SD_Player` | `DoomPlayer` | Сержант. Начинает с `SD_Tokarev`, `SD_Shovel`, 50 `Clip`. Объявляет слоты 1–7. |
| `SD_Shovel` | `Fist` *заменяет Fist* | Слот 1, ближний бой. |
| `SD_Tokarev` | `Pistol` *заменяет Pistol* | Слот 2, `Clip`. |
| `SD_Izh` | `Shotgun` *заменяет Shotgun* | Слот 3, `Shell`. Два ствола, затем перезарядка «переломкой» (`int barrels`). |
| `SD_Ppsh` | `Chaingun` *заменяет Chaingun* | Слот 4, `Clip`. |
| `SD_Rpg7` | `RocketLauncher` *заменяет RocketLauncher* | Слот 5, `RocketAmmo`. Стреляет `SD_Pg7Grenade`. |
| `SD_Roks3` | `PlasmaRifle` *заменяет PlasmaRifle* | Слот 6, `Cell`. Стреляет `SD_FlameBlob`. |
| `SD_HandKatyusha` | `BFG9000` *заменяет BFG9000* | Слот 7, `Cell`, 40 за залп. Стреляет шестью `SD_KatyushaRocket`. |
| `SD_Pg7Grenade` | `Rocket` | Кумулятивный снаряд. Не размещается на карте. |
| `SD_FlameBlob` | `Actor` | Снаряд огня, дальность 528 юнитов. Не размещается на карте. |
| `SD_KatyushaRocket` | `Rocket` | Ракета залпа, не вредит стрелку. Не размещается на карте. |

### 6.1 Номера редактора (DoomEdNums)

**Soviet Doom резервирует 21000–21999.** Прежнее предложение 14000–14999

`AmbientSound` / `SoundSequence` и 14101–14165 — `MusicChanger` (проверено
2026-10-12 по <https://zdoom.org/wiki/Standard_editor_numbers>). Обоснование

### 6.2 Звуки (SNDINFO)

Код никогда не называет ламп напрямую; он называет логический звук. F4
привязывает каждое логическое имя к лампу Freedoom как плейсхолдер.
**`sound-designer` владеет правым столбцом**; заменить звук означает
положить `src/sounds/<LUMP>.ogg` в дерево файлов и отредактировать одну
строку `SNDINFO`.

| Логическое имя | Плейсхолдер F4 | Итоговый ламп для сдачи |
|---|---|---|
| `sd/weapon/shovel/swing` | **нет — беззвучно** | `SDSHSWG` |
| `sd/weapon/shovel/hit` | `DSPUNCH` | `SDSHHIT` |
| `sd/weapon/tokarev/fire` | `DSPISTOL` | `SDTTFIR` |
| `sd/weapon/izh/fire` | `DSSHOTGN` | `SDIZFIR` |
| `sd/weapon/izh/reload` | `DSSGCOCK` | `SDIZRLD` |
| `sd/weapon/ppsh/fire` | `DSPISTOL` | `SDPPFIR` |
| `sd/weapon/rpg7/fire` | `DSRLAUNC` | `SDRPFIR` |
| `sd/weapon/rpg7/explode` | `DSBAREXP` | `SDRPEXP` |
| `sd/weapon/roks3/fire` | `DSFLAME` | `SDRKFIR` |
| `sd/weapon/katyusha/charge` | `DSBFG` | `SDHKCHG` |
| `sd/weapon/katyusha/fire` | `DSRLAUNC` | `SDHKFIR` |
| `sd/weapon/katyusha/burst` | `DSBAREXP` | `SDHKEXP` |

Взмах лопаты **намеренно сделан беззвучным** с 2026-10-13. Он указывал на
`DSSAWUP`, запуск бензопилы, и CEO услышал бензопилу. Единственный ламп
Freedoom для взмаха по воздуху — `DSSKESWG`, замах ревенанта перед ударом в
ближнем бою, который учил бы игрока, что монстр вот-вот его ударит; у
доомовского `Fist` тоже нет звука взмаха. И запись в `SNDINFO`, и вызов
`A_StartSound` в состоянии `Fire` класса `SD_Shovel` убраны, а две строки,
которые их восстанавливают, выписаны в начале `SNDINFO`.
`tests/test_arsenal.py` падает, если любой плейсхолдер указывает на ламп
`*SAW*`. См. `docs/engine/adr/003-ammo-naming-and-the-silent-shovel.md`.

### 6.3 Спрайты, которые предстоит нарисовать (контракт с `art-director`)

Ламп спрайта Doom — это `ИМЯ` + буква кадра + цифра поворота, максимум 8
символов; `0` в качестве поворота означает «одна и та же картинка под любым
углом» — так устроены спрайты оружия на HUD. F4 работает на лампах
Freedoom; имена ниже **зарезервированы** для настоящей графики и свободны
от любого лампа в `freedoom2.wad` (проверено: в IWAD нет ни одного лампа,
начинающегося на `SD`).

| Оружие | В руках (HUD) | Вспышка выстрела | Подбор | Снаряд |
|---|---|---|---|---|
| Сапёрная лопата | `SDSH` A–E | — | `SDSP` A | — |
| ТТ-33 Токарева | `SDTT` A–E | `SDTF` A | `SDTP` A | — |
| ИЖ-58 | `SDIZ` A–F | `SDIF` A–B | `SDIP` A | — |
| ППШ-41 | `SDPP` A–B | `SDPF` A–B | `SDPQ` A | — |
| РПГ-7 | `SDRL` A–B | `SDRF` A–D | `SDRP` A | `SDPG` A–B, разрыв `SDPX` A–C |
| РОКС-3 | `SDRK` A–B | `SDKF` A–B | `SDKP` A | `SDFL` A–B, попадание `SDFX` A–E |
| Ручная «Катюша» | `SDHK` A–C | `SDHF` A–B | `SDHP` A | `SDKR` A–B |

Число кадров повторяет оружие Doom, которое каждый заменяет, так что
существующие конечные автоматы состояний не нужно будет править, когда
придёт арт — только имя из четырёх букв в каждой строке состояния.

**Как выглядят плейсхолдеры Freedoom сегодня** (игровая сессия CEO,
2026-10-13). Это арт-дефекты, а не дефекты движка: мод не задаёт для них
ни `Scale`, ни смещений спрайта, а смещения ниже — это смещения самого
IWAD, и они верны (`left = width / 2`, `top = height`, то есть по центру и
стоя на полу).

| Слот | Используемый плейсхолдер | Что видит CEO | Реальность |
|---|---|---|---|
| 1, в руках | `PUNG` A–D (96×46 / 256×32) | «рукав того же цвета, что и кулак» | Это **и есть** голый кулак: спрайт удара Freedoom, без рукава, без лопаты. Заменяется на `SDSH` A–E. |
| 1, подбор | `CSAW` A | бензопила на полу | Заменяется на `SDSP` A. |
| патроны | `CLIP` 7×12, `AMMO` 17×16, `SHEL` 14×10, `SBOX` 34×13, `ROCK` 10×24, `BROK` 52×20, `CELL` 19×12, `CELP` 32×20, `BPAK` 26×30 | «у патронов нет трёхмерного вида» | Подтверждено: собственная графика подбора Freedoom, плоская и слабо затенённая. В коде исправлять нечего. Советские ящики — арт-долг **T8**. |

Подборы патронов — единственные спрайты IWAD, класс которых мод теперь
*владеет* (§6.4), так что заменить их позже — это правка состояния
`Spawn` в одну строку на класс, без изменений где-либо ещё.

### 6.4 Патроны (контракт с `art-director` и `level-designer`)

Мод не создаёт **новых пулов патронов**: четыре пула Doom — это именно те
четыре, что нужны арсеналу. Чем он владеет — девятью акторами подбора,
объявленными в `zscript/sd/ammo.zs`, чтобы игрок читал советскую
номенклатуру 1977 года вместо «bullets» и «shells» (решение CEO,
2026-10-13).

| Пул | Классы подбора (наши) | Заменяет | Используется | Название (`LANGUAGE`) |
|---|---|---|---|---|
| `Clip` | `SD_Clip`, `SD_ClipBox` | `Clip`, `ClipBox` | ТТ-33, ППШ-41 | `AMMO_CLIP` — 7.62x25 / «Патроны 7,62×25» |
| `Shell` | `SD_Shell`, `SD_ShellBox` | `Shell`, `ShellBox` | ИЖ-58 | `AMMO_SHELLS` — 12 gauge / «Патроны 12 кал.» |
| `RocketAmmo` | `SD_RocketAmmo`, `SD_RocketBox` | `RocketAmmo`, `RocketBox` | РПГ-7 | `AMMO_ROCKETS` — PG-7V / «Выстрелы ПГ-7В» |
| `Cell` | `SD_Cell`, `SD_CellPack` | `Cell`, `CellPack` | РОКС-3, ручная «Катюша» | `AMMO_CELLS` — fuel / «Горючее» |
| — | `SD_Backpack` | `Backpack` | — | строка подбора `SD_GOT_BACKPACK` |

Правила, важные для остальных ролей:

- **Карты продолжают использовать номера редактора Doom** (2007/2048 —
  патроны, 2008/2049 — дробь, 2010/2046 — ракета, 2047/17 — ячейка, 8 —
  рюкзак). Остальное делает `replaces`; наши классы не получают
  собственного номера редактора.
- Каждый класс — подкласс доомовского подбора, который он заменяет.
  Именно это сохраняет пул доомовским: `GetParentAmmo()` поднимается до
  первого потомка `Ammo`. **Никогда** не делайте один из них прямым
  потомком `Ammo` — это незаметно создало бы пятый пул.
- **Строки подбора берутся из идентификаторов `SD_GOT_*`, никогда из
  `GOTCLIP` и ему подобных.** Freedoom переопределяет эти девять
  идентификаторов в своём лампе `DEHACKED`, а замена строки `DEHACKED`
  побеждает ламп `LANGUAGE`, загруженный после неё (проверено в движке,
  2026-10-13). Это закреплено тестом.
- **Английская секция `LANGUAGE` остаётся ASCII, пока не оплачен долг
  T9.** В `SmallFont` Freedoom нет кириллицы — пакет глифов GZDoom лежит в
  `filter/doom.id/`, который Freedoom не выбирает, — поэтому кириллица
  выводится пустыми местами. Проверено: `ПГ-7В` вывелось как ` -7B`, и
  даже `×` вывелся пустым. Кириллица хранится в секции `[ru]` и уже верна.

**Задание для `art-director` (долг T9), механизм проверен.** Если
положить `fonts/defsmallfont/<HEX>.png` в PK3, это расширяет `SmallFont`
GZDoom на Freedoom — проверено 2026-10-13 на двух одноразовых глифах, `П` и
`Г`, которые отрисовались. Набор для отрисовки, в стиле малого шрифта
Freedoom, как `src/fonts/defsmallfont/<HEX>.png`: **U+0410–U+042F** (32
прописные кириллические буквы), **U+0401** (`Ё`), **U+00AB / U+00BB**
(`«»`) и **U+00D7** (`×`). Малый шрифт Doom — только прописной, так что
строчные буквы не нужны. Когда они появятся, английская секция перейдёт на
кириллицу, и русская сборка станет читаемой в том же изменении.

### 6.5 Строка статуса — открытый вопрос для CEO

Слова **AMMO**, **HEALTH**, **ARMS** и **ARMOR**, которые CEO хочет видеть
на кириллице, **не являются текстом**: это пиксели, нарисованные внутри
графики `STBAR` из IWAD (320×32 в `freedoom2.wad`, проверено; серые цифры
оружия — это второй ламп, `STARMS`, 38×32). Ни одна строка `LANGUAGE` до них
не дотягивается. Два выхода, ни один пока не сделан:

| Способ | Что это | Стоимость | Следствие |
|---|---|---|---|
| **Свой `STBAR`** | `art-director` перерисовывает одну графику 320×32 с кириллическими надписями; она ставится как `src/graphics/STBAR.png` и переопределяет ламп IWAD по имени (стандартная замена лампа; **в этом проекте пока не проверено**). | ~1 арт-задача, 0 кода | Дешевле всего. Полоса сохраняет точную раскладку Doom, а числа продолжают работать нетронутыми. Привязано к одному языку — русская и английская сборки показывали бы одну и ту же полосу. |
| **Своя строка статуса** | Ламп `SBARINFO` или подкласс ZScript `BaseStatusBar` рисует всю полосу сами. | ~1 инженерная задача + тот же арт | Полный контроль: локализованные надписи, советская раскладка, наконец видимые собственные `Tag` патронов. Также собственная поверхность для багов, и её придётся перерисовывать для альт-HUD и широкого экрана. |

**Рекомендация: пока ни то, ни другое.** Сначала сделать кириллический
шрифт (T9) — это одна арт-задача, она разблокирует *каждую* строку в игре
вместо четырёх слов, и она в любом случае необходима для локализованной
строки статуса. Затем перерисовать `STBAR` в F6, когда `art-director`
будет делать арт HUD одним проходом. Своя строка статуса на ZScript
оправдана только если мы решим, что сам HUD должен перестать выглядеть
как у Doom.

## 6.6 Меню (`MENUDEF`)

Мод владеет четырьмя фактами о меню. Все четыре были изучены в движке, три
из них — сначала что-то сломав; рассуждение — в
`docs/engine/adr/004-language-switch-and-difficulty-ladder.md`, а строки
исходника движка процитированы прямо в `src/lumps/MENUDEF`.

| Что | Как | Почему это не очевидно |
|---|---|---|
| Переключатель языка | `OptionString "SD_LanguageValues"` со значениями `auto` / `default` / `ru`, управляющий собственным архивируемым CVar `language` движка | `OptionValue` разбирает свой левый столбец как ЧИСЛО, и **игра не запустится**; мод не объявляет ни своего CVar, ни `CVARINFO` |
| Где живёт переключатель | `AddOptionMenu` на **обоих** экранах, `OptionsMenu` и `OptionsMenuSimple`, `BEFORE "os_Menu"` | `m_simpleoptions` по умолчанию true, так что «Options» открывает КОРОТКИЙ экран; добавление в конец помещает строку за пределами видимой области |
| Логотип главного меню | `LISTMENU "MainMenu"` переобъявлен с `StaticPatch 60, 0, "M_DOOM"` | собственное значение движка — `94, 2`, которое не совпадает с леттерингом, нарисованным в `TITLEPIC` (контракт — `work/art/shell/manifest.json`: x=60, y=0) |
| Названия сложностей | `LISTMENU "SkillMenu"` переобъявлен с `Font "SmallFont", "Red", "Gold"` | стандартный BigFont вмещает ~26 символов, а ступень 5 — 38; названия — от CEO, и шрифт — та часть, которую мы можем менять |

ZScript здесь не задействован вообще. Мод может писать в CVar из ZScript
только пока движок обрабатывает ввод меню — `DMenu::InMenu` поднимается
вокруг `OnUIEvent`, `OnInputEvent` и `MenuEvent` и ни вокруг чего больше
(`src/common/menu/menu.cpp`), — так что запись из `Init`, `Ticker` или
`Drawer` аварийно завершает VM и выбрасывает игрока в консоль. **Не
добавляйте класс ZScript для меню, который пишет в CVar.**

Три переобъявленных меню — буквальные копии собственных тел GZDoom 4.14.2
с изменённой в каждой одной строкой. Пересверяйте их с
`gzdoom.pk3/menudef.txt` при каждом обновлении движка (долг T14).

## 7. Команды

```sh
python3 tools/build.py                       # → dist/sovietdoom.pk3
python3 tools/build.py --print-textmap MAP01 # показать сгенерированный UDMF
python3 -m unittest discover -s tests -v     # тесты сборки
tools/run.sh                                 # сборка + gzdoom + logs/gzdoom.log
MAP=MAP02 tools/run.sh                       # тестовый полигон арсенала F4
MAP=MAP01 SKILL=4 IWAD=/path/doom2.wad tools/run.sh -nosound
tools/run.sh -nosound +vid_fullscreen 0 +screenshot_dir "$PWD/logs/shots" +"wait 140; screenshot; wait 35; quit"  # доказательства QA
python3 tools/smoke.py --map MAP01 --skill 4 [--keep-evidence]  # сборка + самозавершающийся запуск GZDoom + разбор лога (код 0 = чисто)
python3 tools/check_pk3.py [--json] [--strict]   # статическая проверка PK3 без движка: лампы, WAD-файлы карт, используемые текстуры, палитра PNG, спрайты, лицензии, #include (код 0 = чисто)
```

`run.sh` ищет GZDoom в `/Applications/GZDoom.app/Contents/MacOS/gzdoom`,
`~/Applications/…` и `PATH` (или `GZDOOM=`), а IWAD — в `iwads/`,
`~/Library/Application Support/gzdoom/` и `$DOOMWADDIR` (или `IWAD=`),
предпочитая `freedoom2.wad`. Всегда пишет `logs/gzdoom.log`; `qa-engineer`
ищет в нём `Script error`, `Unknown texture`, `Missing sprite`: любое
совпадение — провал. `screencapture` в macOS не видит окно игры; используйте
команду `screenshot` движка.

## 9. Баланс

Каждое игровое число арсенала и причина, по которой оно такое, живёт в
`docs/engine/BALANCE.md`. Этот файл владеет *именами и структурой*; тот —
*значениями*. Код владеет и тем, и другим как именованные константы — если
документ и код расходятся, прав код, а документ — ошибка.
