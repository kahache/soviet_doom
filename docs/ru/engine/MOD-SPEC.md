Минимальный глоссарий (для новичков в моддинге Doom):

- **IWAD**: файл данных базовой игры (`doom2.wad` или `freedoom2.wad`). Без него
  GZDoom не запускается.
- **PK3**: `.zip` с фиксированной структурой папок, который GZDoom монтирует
  поверх IWAD. Формат мода.
- **Ламп (lump)**: именованный блок данных (не более 8 символов ASCII). В PK3
  каждый файл — ламп, названный по имени файла без расширения.
- **UDMF**: текстовый формат карты (`TEXTMAP`), используемый GZDoom; мы
  генерируем его из Python.
- **DoomEdNum**: число, которым редактор карт обозначает размещаемый объект;
  `1` — «Player 1 start».

## 2. Структура PK3 (выход)

```
sovietdoom.pk3
├── MAPINFO                 карты, эпизоды, уровни сложности, GameInfo (AddEventHandlers, PlayerClasses)
├── LANGUAGE                локализованный текст: [enu default] и [ru] (D7)
├── MENUDEF                 переключатель языка, главное меню и экран сложности нашим шрифтом (§6.6)
├── SNDINFO                 логическое имя звука -> ламп (F4)
├── zscript.txt             вход ZScript: version + #include
├── zscript/sd/*.zs         системы (обработчики событий, класс игрока, патроны)
├── zscript/weapons/*.zs    арсенал, один класс на файл (F4)
├── zscript/monsters/*.zs   бестиарий, один класс на файл (F5, BESTIARY.md)
├── maps/MAP01.wad          один WAD на карту, лампы MAP01, TEXTMAP, ENDMAP
├── maps/MAP02.wad          инженерный тестовый полигон (F4)
├── textures/SD*.png        одобренные текстуры стен: SDCONC1-2, SDDOOR1, SDPOSTR1-2, SDSTAR1,
│                           SDSTEL1 и восемь лиц переключателей SDSW1A-D / SDSW2A-D (§4.3)
├── flats/SD*.png           одобренные флэты: SDFLR1-3, SDCEIL1-2
├── graphics/TITLEPIC.png   титульный экран, 320×200 (D18)
├── graphics/INTERPIC.png   фон интермишна, 320×200 (D18)
├── graphics/M_DOOM.png     логотип главного меню, 200×64, ставится MENUDEF (§6.6)
├── fonts/defsmallfont/     <HEX>.png + font.inf — глифы SmallFont, 107 файлов (D24)
├── fonts/bigfont/          <HEX>.png + font.inf — глифы BigFont, 107 файлов (D24)
├── fonts/sdmenu/           <HEX>.png + font.inf — шрифт меню SDMENU, 107 файлов (D31, §6.6)
├── music/D_SDINTL.mid       музыка титульного экрана, «Интернационал» Энгельбаха (D43, §4.5)
├── music/D_SDM01.mid        музыка MAP01, наша (D43, §4.5)
├── sprites/  sounds/  patches/  hires/   стандартные папки, сегодня пустые (T1)
├── ANIMDEFS                пары переключателей SDSW1x -> SDSW2x (§4.3)
└── (будущее) TEXTURES, GLDEFS — и без CVARINFO, по решению (ADR 004)
```

Правила:
- Файлы в корне: имя ≤ 8 символов без расширения (сборка проверяет и падает иначе).
- Шрифты — это **шрифты-папки**: GZDoom читает `fonts/<fontname>/<HEX>.png`,
  один PNG на кодовую точку в верхнем регистре hex (`0410.png` = `А`), плюс
  `font.inf` (`FontHeight 9` малый, `FontHeight 16` большой). `defsmallfont` —
  имя папки, которую `SmallFont` движка опрашивает на глифы, которых ему
  не хватает, так что наши PNG **расширяют** малый шрифт Freedoom (механизм
  проверен в движке 2026-10-13 на двух глифах, §6.4); `bigfont` назван по
  самому `BigFont`. **НЕ ПРОВЕРЕНО**: заменяет ли `fonts/bigfont/` `BigFont`
  Freedoom или расширяет его — движок загружает пакет без ошибок и
  титульный экран отрисовывается (коммит 730bba4), но скриншота кириллической
  строки BigFont пока не снято. `sdmenu` — **самостоятельный** шрифт: он
  ничего не расширяет, поэтому несёт все глифы, которые рисует (§6.6).
- Лампы карт: `MAP01`, `MAP02`, … (формат Doom II). Внутри WAD порядок
  фиксирован: маркер `MAPxx` (пустой), `TEXTMAP`, `ENDMAP` (пустой). Без лампов
  нод: GZDoom строит их при загрузке (проверено на G0).
- Карты не распаковываются: GZDoom читает `maps/MAP01.wad` напрямую.

## 3. Структура `src/` (вход сборки)

```
src/
├── lumps/        → корень PK3 (плоско: MAPINFO, LANGUAGE, MENUDEF, SNDINFO, ANIMDEFS, zscript.txt)
├── zscript/      → zscript/  (копируется как есть; sd/ = системы, weapons/ = арсенал, monsters/ = бестиарий)
├── maps/MAP01/map.py   → maps/MAP01.wad  (генерируется; определяет lumps())
├── maps/MAPxx.wad      → maps/MAPxx.wad  (копируется как есть; выход UDB)
└── textures/ flats/ sprites/ sounds/ music/ graphics/ patches/ hires/ fonts/ → те же пути

assets/   (только арт, одобренный CEO; `work/` в gitignore и никогда не поставляется)
├── <folder>/<set>/NAME.png → <folder>/NAME.png   папка набора ОТБРАСЫВАЕТСЯ
│     напр. assets/textures/soviet_base/SDCONC1.png → textures/SDCONC1.png
│           assets/graphics/shell/TITLEPIC.png      → graphics/TITLEPIC.png
└── fonts/<fontname>/*      → fonts/<fontname>/*   сохраняется целиком: папка И ЕСТЬ шрифт
```

- **Отображение ассетов** (`tools/build.py`, упаковщик
  `tools/sdbuild/pk3.py`, `collect_assets`). Для каждой стандартной папки
  (`textures`, `flats`, `sprites`, `sounds`, `music`, `graphics`, `patches`,
  `hires`, `fonts`) файл `assets/<folder>/<set>/NAME.png` упаковывается как
  `<folder>/NAME.png`: набор (`soviet_base`, `shell`) — это группировка для
  ревью, а GZDoom называет ламп по имени файла, поэтому набор отбрасывается
  при упаковке, и `SDCONC1` с карты находится. `fonts/` — единственное
  исключение (`NESTED_ASSET_DIRS`): `assets/fonts/<fontname>/…` сохраняет
  свой путь, потому что имя подпапки — это и есть шрифт (D24).
  `src/<folder>/` упаковывается по тем же путям; путь, полученный дважды —
  из `src/` и из `assets/` или из двух наборов с одинаковым именем файла, —
  роняет сборку (`duplicate PK3 path`). Это отображение было блокером
  **M1** (2026-10-12): одобренный арт лежал в `assets/` и не попадал в PK3,
  так что каждая карта, ссылающаяся на него, падала с `Unknown texture`.
  Его держат `tests/test_build.py` и `tools/check_pk3.py`.
- Хвосты редакторов в `src/lumps/` (`.bak`, `.orig`, `.rej`, `.tmp`,
  `.swp`, `~`, точечные файлы) пропускаются, как и `.DS_Store`, `Thumbs.db`
  и `__pycache__` в любом месте: иначе `MAPINFO.bak` стал бы вторым лампом
  `MAPINFO` (замечено 2026-10-13).

- Генерируемая карта (`map.py`) предоставляет `lumps() -> list[(name, bytes)]`,
  первый ламп — маркер с именем папки. Импортирует `sdbuild.udmf` для сборки
  `TEXTMAP` (`tools/sdbuild/udmf.py`).
- `level-designer` может сдать `.wad`, сделанный в Ultimate Doom Builder, в
  `src/maps/`; сборка упаковывает его без изменений. Имя файла = имя карты.
- Сборка детерминирована (фиксированные метки времени, отсортированные записи):
  одни и те же исходники дают идентичные байты (есть тест).

### 4.4 Учебный полигон (D41, 2026-10-13)

CEO: "Se puede publicar como práctica". MAP02 поставляется в v1 **вне
кампании**, и игрок попадает на неё с экрана «Новая игра». Выбор между
способами попасть на неё — ADR 007
(`docs/engine/adr/007-practice-range-as-a-second-episode.md`); контракт:

| Что | Значение |
|---|---|
| Эпизоды (`MAPINFO`, в таком порядке) | `episode MAP01` name `$SD_EP01_NAME`, key `s`; `episode MAP02` name `$SD_EP02_NAME`, key `p` |
| Названия эпизодов | `SD_EP02_NAME` = "Practice Range" / «Полигон» (название карты `SD_MAP02_NAME` не меняется) |
| Поток | Главное меню → «Новая игра» → **экран эпизода** (новый: при одном эпизоде движок его пропускал) → экран сложности → карта |
| Экран эпизода (`MENUDEF`) | `LISTMENU "EpisodeMenu"`, переобъявленный так же, как экран сложности (§6.6): логотип `M_DOOM` в 60,0, один заголовок `SDMENU` `$SD_MNU_CHOOSEEPISODE` в 32,70 ("CHOOSE MISSION" / «ВЫБЕРИТЕ ЗАДАНИЕ»), затем `SmallFont` для названий эпизодов, которые движок добавляет во время выполнения. **`M_EPISOD` не рисуется никогда** (T12) |
| Выход MAP01 | `next = endtitle`, без изменений: кампания заканчивается; **`next` ни одной карты не равен MAP02** |
| Выход MAP02 | `cluster = 2`, `next = endtitle`: выход из полигона показывает `SD_END02_TEXT` ("The range is closed…" / «Полигон закрыт…») поверх `SDFLR1`, затем титульный экран. `nointermission` остаётся: у полигона нет счёта, достойного экрана статистики. Игрок уходит через **переключатель выхода за стартом** (`Exit_Normal`, нажатием; коммит `d1e891f`, `docs/levels/MAP02-practice-range.md` §4.1). **Увидено в движке** 2026-10-13: нажатие показывает `SD_END02_TEXT` поверх `SDFLR1` (P6 в `docs/qa/evidence/2026-10-13_2057_map02-range-and-c12.md`). Маршрут `map02-start` в `tools/route.py` (с route-3) нажимает тот же переключатель, как это делает игрок (`docs/qa/evidence/2026-10-13_2114_F3_g3-map02-map02-start-*`); `netevent sdexit` помощника маршрутов (`Level.ExitLevel`) — лишь документированное средство на крайний случай для карты без линии выхода, и ни один встроенный маршрут его не использует. **Консольная команда `exit` до него не доходит: она закрывает GZDoom** (G3-F2) |
| Кластер 2 | `exittext = lookup, "SD_END02_TEXT"`, `flat = "SDFLR1"`, `music = ""` |

Факты движка, на которых это держится, прочитаны в GZDoom g4.14.2
(`gzdoom.pk3 → menudef.txt`, `ListMenu "EpisodeMenu"`, и построитель меню
эпизодов в исходниках движка, `M_StartupEpisodeMenu`, не файл этого
репозитория): меню перечисляет по одному пункту на каждый `episode` из
MAPINFO в **последнем** `Font` дескриптора, начиная с его `Position`, под
любыми статическими пунктами; эпизод без `picname` получает текстовый пункт;
при ровно одном эпизоде пункт выбирается автоматически и экран не
показывается, поэтому `M_EPISOD` до сих пор не появлялся. Собственное тело
движка ещё задаёт `NetgameMessage "$NEWGAME"` («Новая игра» запрещена в
сетевой игре); наше его сохраняет.

**Прогон в движке, сделан 2026-10-13** (PM; D26):

не изменилось: MAPINFO, кластер и эпизод — как выше.

### 4.5 Музыка (D43, 2026-10-13)

CEO принял все музыкальные рекомендации `docs/sound/SOUNDTRACK.md` §8 (D43);
`sound-designer` установил первые два ламп в `assets/music/` (коммит
`d89f99e`, права в `docs/sound/MUSIC-RIGHTS.md`, строки в
`docs/art/LICENSES.md`), а сборка упаковывает их как `music/<LUMP>.mid`
(отображение ассетов, §3). `MAPINFO` называет их; `SNDINFO` не
задействован (музыкальные ламп — не звуки).

| Где | Ключ `MAPINFO` | Ламп |
|---|---|---|
| Титульный экран | `GameInfo { TitleMusic = "D_SDINTL" }` | `D_SDINTL`, «Интернационал» (секвенция Энгельбаха, с указанием авторства) |
| MAP01, Заря-7 | `map MAP01 { music = "D_SDM01" }` | `D_SDM01`, наш |
| MAP02, учебный полигон | `music = ""` | нет |
| Кластеры 1 и 2 (тексты концовок) | `music = ""` | нет |

Правило: каждое значение `music` / `TitleMusic` — это `""` или ламп,
упакованный в `music/` (`tests/test_mapinfo_music.py`); опечатка ничего не
играет и ничего не пишет в лог, поэтому это тест, а не находка прогона в
движке. `TitleMusic` в `GameInfo` мода переопределяет значение IWAD
(`D_DM2TTL` на Freedoom) тем же слиянием блоков, которое уже несёт
`PlayerClasses`.
**Прогон в движке, 2026-10-13** (PM,
`docs/qa/evidence/2026-10-13_2039_d40-d43-engine-pass.md`): **ПРОВЕРЕНО**,
что `currentmusic` сообщает `D_SDM01` на MAP01 и отсутствие музыки на MAP02.
**По-прежнему НЕ ПРОВЕРЕНО:** `D_SDINTL` титульного экрана (тот прогон
стартует в карте, так что титульный экран не звучал) и то, что музыка
титула продолжается в главном меню, как у Doom.

### 4.1 Как заканчивается кампания (M3, закрыт 2026-10-13)

`Exit_Normal` на MAP01 завершает игру. Три факта, все проверены в движке,
нужны каждому, кто тронет это место:

- **Текст конца эпизода принадлежит КЛАСТЕРУ, а не карте.** Очевидное
  `next = EndGame { Text = "…" }` не парсится: блок endgame принимает
  только `pic`, `hscroll`, `vscroll`, `cast` и `music`
  (`ParseEndGame`, gzdoom: src/intermission/intermission_parse.cpp, исходник движка, не файл этого репозитория), и GZDoom
  отвечает `Unknown property 'Text' found in endgame definition`. Нужная
  запись — `cluster 1 { exittext = lookup, "SD_END01_TEXT" flat =
  "SDFLR1" }`.
- **`next = endtitle`** — именованная концевая последовательность для
  «проиграть финал, затем вернуться на титульный экран» (`CheckEndSequence`,
  тот же файл).
- **`nointermission` убран из MAP01.** Раньше нажатие на выход бесшумно
  перезапускало карту; экран статистики теперь впервые сообщает, что
  уровень пройден. `par = 210` — цифра `level-designer`. **НЕ ПРОВЕРЕНО**:
  что экран выводит 3:30 — строка PAR появляется, но её значение
  анимируется вверх и не стабилизировалось за время автоматического
  прогона без участия человека. QA, с человеком за клавиатурой.

### 4.2 Используемые спешлы карты (M5, из §9 `level-designer`)

ЧИСЛА line-special ZDoom вкомпилированы в движок, а не поставляются в
каком-либо файле, поэтому их проверили единственным оставшимся способом:
прошли карту в v0 и посмотрели, как движется геометрия. Доказательства — в
`docs/levels/shots/`. *Формы* аргументов всё же поставляются, в
`gzdoom.pk3 → xlat/`.

| Спешл | № | Аргументы | Для чего используется | Статус |
|---|---|---|---|---|
| `Door_Raise` | **12** | `(tag, speed, delay, lighttag)`, задан как `(tag, 16, 150, 0)` | ручная дверь, открываемая с обеих сторон; `playeruse` + `repeatspecial` | **ПРОВЕРЕНО в движке** 2026-10-13 |
| `Door_Open` | **11** | `(tag, speed, lighttag)`, задан как `(tag, 16, 0)`, а с MAP01 v2 — как `(10, 16, 30)` на SW-A | нажимная панель, которая остаётся открытой; односторонний настенный переключатель, открывающий удалённую дверь по тегу; при заданном lighttag секторы с этим тегом становятся ярче, пока дверь открывается | **ПРОВЕРЕНО в движке** 2026-10-13; lighttag — 2026-10-13 16:11 (кабина, видимая через своё окно, из тёмной становится освещённой). | `Exit_Normal` | **243** | `(pos)` | переключатель выхода с уровня | **ПРОВЕРЕНО в движке** 2026-10-13; с этого изменения завершает игру (§4.1), а не перезагружает MAP01 |

Константы из `xlat/defines.i`: `D_SLOW = 16`, `VDOORWAIT = 150`. Теги —
это UDMF `id` на секторе и `arg0` на линии.

Два факта о движке, каждый стоивший `level-designer` одной пересборки,
записаны здесь, чтобы следующий человек не платил снова:

- Спешл `playeruse` срабатывает **только с лицевой стороны линии**, так
  что двери нужен спешл на *обеих* обрамляющих линиях, каждая из которых
  обращена к двери своей ЗАДНЕЙ стороной. `LineStyle.back_sector` в
  `tools/sdbuild/udmf.py` делает это, а `tests/test_udmf.py` это
  проверяет.
- `Door_Raise` / `Door_Open` поднимают дверь до **(потолок ближайшего
  соседа − 4)**, так что дверь, открытая со стороны низкого соседа, может
  оказаться непроходимой.

Спешлы секторов, номера из `gzdoom.pk3 → xlat/defines.i`:

| Спешл сектора | № | Для чего используется | Статус |
|---|---|---|---|
| `dLight_Flicker` | **65** | мерцающий участок Z5 (MAP01 v2) | **ПРОВЕРЕНО в движке** 2026-10-13 16:11: средняя яркость 61 → 46 → 61 на трёх кадрах с интервалом 5 тиков |
| `SECRET_MASK` | **1024** | три секретных сектора S1-S3 | **ПРОВЕРЕНО в движке** 2026-10-13 16:11: каждый выводит сообщение о секрете при входе |

### 4.3 Текстуры переключателей и их ANIMDEFS (T16)

Восемь лиц переключателей одобрены и поставляются в `textures/` (пакет 2,
2026-10-13; каждое 64×128, один сегмент стены на сетке 64; происхождение и
лицензия — в `docs/art/LICENSES.md`): `SDSW1A`–`SDSW1D` и
`SDSW2A`–`SDSW2D`. **Соглашение об именах с этого момента является
контрактом**, и оно — собственное доомовское (`SW1BRCOM` / `SW2BRCOM`):

| Символы | Значение |
|---|---|
| `SDSW` | префикс мода + «switch» |
| `1` / `2` | состояние: **1 = выключено** (не нажато), **2 = включено** (нажато). Два лампа пары различаются только этой цифрой |
| последняя буква `A`–`D` | вариант дизайна (A — рубильник, B — куполообразная кнопка, C — ползунковый рычаг, D — панель опасности) |

Имя, которое использовало задание, `SDSWT1`/`SDSWT2` (пункт A3 дизайна
уровня, `tools/art/gen_switch.py`), отозвано: одобрены четыре варианта, а
не один, и букве варианта нужен восьмой символ.

Объявление, которое заставляет движок **менять 1 на 2**, когда линию
используют, — это `src/lumps/ANIMDEFS`, упаковываемый сборкой как корневой
ламп `ANIMDEFS` без других изменений (§3). Одна строка на пару:

```
switch doom 1 SDSW1A on pic SDSW2A tics 0
switch doom 1 SDSW1B on pic SDSW2B tics 0
switch doom 1 SDSW1C on pic SDSW2C tics 0
switch doom 1 SDSW1D on pic SDSW2D tics 0
```

- **Синтаксис проверен по собственным определениям движка**, а не по вики
  (всё ещё недоступной 2026-10-13): GZDoom g4.14.2 поставляет
  `animdefs.txt` в корне `gzdoom.pk3`, и строки 194-235 объявляют каждый
  переключатель Doom ровно в этой форме (`switch doom 1 SW1BRCOM on pic
  SW2BRCOM tics 0`). `doom` — фильтр игры (IWAD семейства Doom, а именно их
  поддерживает §1); число — самая старая версия Doom, в которой пара
  существует (1 shareware, 2 registered, 3 Doom II), и 1 — самое
  разрешающее; следующее имя — OFF, `on pic` называет ON, `tics 0`
  удерживает картинку ON без анимации. Голая форма без фильтра игры НЕ
  ПРОВЕРЕНА и не используется.
- **Без `sound`.** Ни одна строка переключателей Doom в движке его не несёт
  (только у Hexen и Strife); щелчок — это умолчание движка
  `switches/normbutn` → `DSSWTCHN`
  (`gzdoom.pk3 → filter/game-doomchex/sndinfo.txt`), `switches/exitbutn` на
  линиях выхода. Выведено из этого файла; НЕ ПРОВЕРЕНО, пока не услышано в
  движке.
- **ПРОВЕРЕНО в движке, 2026-10-13 14:34** (GZDoom g4.14.2 + Freedoom
  0.13.0, Windows): `SDSW1A` переключается в `SDSW2A`, когда игрок нажимает
  на него, а во втором прогоне собственный `SW1BRCOM` Freedoom всё так же
  переключается в `SW2BRCOM` при загруженном нашем лампе, так что `ANIMDEFS`
  мода **добавляется** к определениям движка, а не заменяет их. Метод:
  одноразовая карта 256×256 (не в репозитории) с переключателем в виде
  односторонней линии `Door_Open` в 56 юнитах перед стартом игрока и
  консольной последовательностью `wait 70; screenshot; wait 10; +use; wait
  4; -use; wait 70; screenshot; quit`. Ноль строк шаблонов сбоев в обоих
  логах. Свидетельство, до и после для обоих:
  `docs/qa/evidence/2026-10-13_1434_F2_t16-switch-flip.png`. Варианты B, C и
  D используют ту же форму строки и по отдельности не нажимались.
  **Всё ещё НЕ ПРОВЕРЕНО:** щелчок, который прогон без человека услышать не
  может.
- `SWITCHES`, бинарный ламп Boom, не используется: непрозрачен для `git
  diff` и для `check_pk3.py`, и не делает ничего, чего не делал бы
  `ANIMDEFS`.
- Защищено `tests/test_animdefs.py` (одна строка на каждую одобренную пару,
  каждый SDSW1x к своему SDSW2x, каждое имя в `assets/`, ламп в корне PK3) и
  `tools/check_pk3.py`, чья проверка `textures` подчиняет каждое имя
  переключателя из ANIMDEFS тому же правилу, что и текстуру карты (в PK3 или
  в §5).

MAP01 v2 носит настоящие лица: SW-A = `SDSW1A`, SW-B = `SDSW1B`, выход =
`SDSW1D` (`SWITCH_PLACEHOLDER` исчез). Все три переключились в прогоне v2 в
движке 2026-10-13. Повторяемый переключатель возвращается в OFF после
короткой задержки (поведение Doom, здесь НЕ ПРОВЕРЕНО), поэтому SW-A и SW-B
одноразовые.

## 5. Используемые ассеты IWAD

Мод не распространяет ничего из IWAD. Freedoom сохраняет имена лампов Doom II,
поэтому ссылка по имени работает на обоих. Каждая ссылка на IWAD должна быть
здесь и в индексе текстур `art-director` с пометкой «IWAD».

|---|---|---|---|
| `STARTAN2` | текстура стены 64×128 | MAP01, 4 стены | проверено на freedoom2.wad 0.13.0 (скриншот G0) |
| `FLOOR4_8` | флэт (пол) | MAP01 | проверено |
| `CEIL3_5` | флэт (потолок) | MAP01 | проверено |

Неявно используемые элементы IWAD: HUD и строка статуса, четыре пула
патронов (`Clip`, `Shell`, `RocketAmmo`, `Cell`) с их подборами и классы
оружия Doom, от которых наследуется арсенал. Начиная с F4 пешка игрока и все
семь видов оружия — **наши** (§6); оружие Freedoom заменено, а
супердробовик и кулак нельзя разместить на карте.

`MAP02` дополнительно размещает номера редактора Doom как **тестовые
заготовки**: взрывающаяся бочка (2035), зомби (3004), аптечка (2012), синяя
броня (2019), рюкзак (8) и ящики патронов 2046/2048/2049/17. С F5 шесть
мишеней 3004 порождают **`SD_ReichRifleman`** (`replaces ZombieMan`), так что

## 6. ZScript

- Вход: `zscript.txt` с `version "4.12"` и только `#include`.
- Один класс на файл. `zscript/sd/` содержит системы, `zscript/weapons/` —
  арсенал, `zscript/monsters/` — бестиарий. Имена классов с префиксом
  `SD_`.
- Обработчики событий регистрируются в `MAPINFO → GameInfo → AddEventHandlers`.

**Слот 1 с D40 (2026-10-13): ледоруб.** CEO заменил сапёрную лопату
ледорубом (piolet, «ледоруб»), зная о ассоциации с Меркадером (`docs/PRD.md`

(`BALANCE.md` §4), номер редактора остаётся **21001**, так что обе карты
работают без изменений, класс по-прежнему `replaces Fist`, и его по-прежнему
находят на стойке в общежитии MAP01, а не выдают. Меняются все имена, где
было «shovel»; эта таблица — контракт, по которому `art-director` и
`sound-designer` называют свои черновики:

|---|---|---|

"Ice axe" — простое английское название, которое напечатало бы пособие
альпиниста 1970-х или перевод слова «ледоруб»; "piolet" — французское
заимствование, которым английский тоже пользуется, оставлено вне игры как
слишком техническое. `SDAX`/`SDAP` и `SDAXSWG`/`SDAXHIT` проверены на
свободу: ни один ламп `freedoom2.wad` 0.13.0 не начинается с `SD`, и ни одно
другое зарезервированное имя в §6.2, §6.3 или бестиарии не начинается с
`SDA`. Зона MAP01 `shovel_rack` (сектор общежития) сначала осталась как
была, поскольку имена зон — за `level-designer`; с коммита `f3cd8ea`
(2026-10-13) она называется **`z1_ice_axe_rack`**, а префикс `z1_` относит
её к Z1 для `tools/route.py` (`docs/levels/MAP01-zarya-7.md` §17.15).

**Прогон в движке, 2026-10-13** (PM,
`docs/qa/evidence/2026-10-13_2039_d40-d43-engine-pass.md`): вход в стойку
общежития MAP01 выводит "An ice axe.", а `printinv` перечисляет
`SD_IceAxe`. Увиденные спрайты были плейсхолдерами Freedoom; `SDAX`/`SDAP` и
`SDAXSWG`/`SDAXHIT` — черновики у гейта CEO.

### 6.2 Звуки (SNDINFO)

Код никогда не называет ламп напрямую; он называет логический звук. F4

### 6.3 Спрайты, которые предстоит нарисовать (контракт с `art-director`)

### 6.4 Патроны (контракт с `art-director` и `level-designer`)

Мод не создаёт **новых пулов патронов**: четыре пула Doom — это именно те
четыре, что нужны арсеналу. Чем он владеет — девятью акторами подбора,
объявленными в `zscript/sd/ammo.zs`, чтобы игрок читал советскую
номенклатуру 1977 года вместо «bullets» и «shells» (решение CEO,
2026-10-13).

| Пул | Классы подбора (наши) | Заменяет | Используется | Название (`LANGUAGE`) |
|---|---|---|---|---|
| `Clip` | `SD_Clip`, `SD_ClipBox` | `Clip`, `ClipBox` | ТТ-33, ППШ-41 | `AMMO_CLIP` — 7.62x25 / «Патроны 7,62×25» |
| `Shell` | `SD_Shell`, `SD_ShellBox` | `Shell`, `ShellBox` | ИЖ-58 | `AMMO_SHELLS` — 12 gauge / «Патроны 12 кал.» |
| `RocketAmmo` | `SD_RocketAmmo`, `SD_RocketBox` | `RocketAmmo`, `RocketBox` | РПГ-7 | `AMMO_ROCKETS` — PG-7V / «Выстрелы ПГ-7В» |
| `Cell` | `SD_Cell`, `SD_CellPack` | `Cell`, `CellPack` | РОКС-3, ручная «Катюша» | `AMMO_CELLS` — fuel / «Горючее» |
| — | `SD_Backpack` | `Backpack` | — | строка подбора `SD_GOT_BACKPACK` |

Правила, важные для остальных ролей:

- **Карты продолжают использовать номера редактора Doom** (2007/2048 —
  патроны, 2008/2049 — дробь, 2010/2046 — ракета, 2047/17 — ячейка, 8 —
  рюкзак). Остальное делает `replaces`; наши классы не получают
  собственного номера редактора.
- Каждый класс — подкласс доомовского подбора, который он заменяет.
  Именно это сохраняет пул доомовским: `GetParentAmmo()` поднимается до
  первого потомка `Ammo`. **Никогда** не делайте один из них прямым
  потомком `Ammo` — это незаметно создало бы пятый пул.
- **Строки подбора берутся из идентификаторов `SD_GOT_*`, никогда из
  `GOTCLIP` и ему подобных.** Freedoom переопределяет эти девять
  идентификаторов в своём лампе `DEHACKED`, а замена строки `DEHACKED`
  побеждает ламп `LANGUAGE`, загруженный после неё (проверено в движке,
  2026-10-13). Это закреплено тестом.
- **Английская секция `LANGUAGE` всё ещё ASCII, и после D24 больше не
  обязана быть ею (T17).** До 2026-10-13 в `SmallFont` Freedoom не было
  кириллицы — пакет глифов GZDoom лежит в `filter/doom.id/`, который
  Freedoom не выбирает, — поэтому кириллица выводилась пустыми местами
  (проверено: `ПГ-7В` вывелось как ` -7B`, и даже `×` вывелся пустым). Это
  был долг **T9**, и D24 оплатил его в тот же день: мод поставляет
  собственные глифы (§2). Секция `[ru]` была верна с самого начала.
  Английские обозначения пока остаются латинской транслитерацией
  (`PG-7V rounds`, `7.62x25`); перевод их на кириллические формы, которых
  требует D17, — это изменение текста плюс переворот
  `tests/test_language.py::test_english_section_is_ascii` и его двойника в
  `tests/test_arsenal.py`, и ему нужен проход по движку, чтобы увидеть
  глифы на HUD. Долг **T17**, здесь не сделан.

**T9 — оплачен (D24, 2026-10-13).** Механизм сначала был проверен
2026-10-13 на двух одноразовых глифах, `П` и `Г`: PNG в
`fonts/defsmallfont/<HEX>.png` расширяет `SmallFont` GZDoom на Freedoom.
Затем `art-director` сдал полный набор из `tools/art/gen_font.py` (стиль C
«Mashina», нарисован по данным штрихов, лицензия гарнитуры не наследуется)
в обоих размерах: ASCII U+0020–U+0060, **U+0410–U+042F** (32 прописные
кириллические буквы), **U+0401** (`Ё`), `«»`, `×`, `°`, `·`, короткое и
длинное тире, `…` и `№` — 107 файлов на шрифт, 214 всего, только
прописные, потому что таковы шрифты Doom. Диапазон ASCII включён, чтобы
латиница и кириллица были написаны одной рукой. Строки лицензий:
`docs/art/LICENSES.md`.

### 6.5 Строка статуса — открытый вопрос для CEO

Слова **AMMO**, **HEALTH**, **ARMS** и **ARMOR**, которые CEO хочет видеть
на кириллице, **не являются текстом**: это пиксели, нарисованные внутри
графики `STBAR` из IWAD (320×32 в `freedoom2.wad`, проверено; серые цифры
оружия — это второй ламп, `STARMS`, 38×32). Ни одна строка `LANGUAGE` до них
не дотягивается. Два выхода, ни один пока не сделан:

| Способ | Что это | Стоимость | Следствие |
|---|---|---|---|
| **Свой `STBAR`** | `art-director` перерисовывает одну графику 320×32 с кириллическими надписями; она поставлялась бы как src/graphics/STBAR.png (планируемый путь, **в дереве его пока нет**) и переопределяла бы ламп IWAD по имени (стандартная замена лампа; **в этом проекте пока не проверено**). | ~1 арт-задача, 0 кода | Дешевле всего. Полоса сохраняет точную раскладку Doom, а числа продолжают работать нетронутыми. Привязано к одному языку — русская и английская сборки показывали бы одну и ту же полосу. |
| **Своя строка статуса** | Ламп `SBARINFO` или подкласс ZScript `BaseStatusBar` рисует всю полосу сами. | ~1 инженерная задача + тот же арт | Полный контроль: локализованные надписи, советская раскладка, наконец видимые собственные `Tag` патронов. Также собственная поверхность для багов, и её придётся перерисовывать для альт-HUD и широкого экрана. |

**Рекомендация: пока ни то, ни другое.** Кириллический шрифт был
необходим для локализованной строки статуса, и он оплачен (T9, D24,
2026-10-13). Перерисовать `STBAR` в F6, когда `art-director` будет делать
арт HUD одним проходом. Своя строка статуса на ZScript оправдана только
если мы решим, что сам HUD должен перестать выглядеть как у Doom.

### Шрифт меню `SDMENU` (D31, собран `art-director`)

`fonts/sdmenu/` — шрифт-папка (§2): `assets/fonts/bigfont/` — алфавит C
«Машина», D24, высота заглавной 11 + 1 px тени, `FontHeight 16` — скопирован
байт в байт, в котором ровно **пять** латинских заглавных перерисованы
кириллическими формами, D22 уровень 2: `0052` R → Я, `004E` N → И,
`0045` E → Э, `0057` W → Ш, `0041` A → Д. Генератор: `tools/art/gen_menu.py`;
эталонный лист: `docs/art/previews/2026-10-13_1554_F2_menu-sweep.png`.

**Один шрифт обслуживает оба языка.** Подстановка живёт в пяти латинских
кодовых точках. Строки `[ru]` записаны кириллическими кодовыми точками
(U+0400–U+04FF), которых шрифт не трогает, поэтому русский читается как
настоящий русский, а английский — «ИЭШ GДMЭ». `LANGUAGE` хранит корректный
английский — пригодный для поиска, перевода и сравнения, — таково правило
D22: отображение — дело шрифта, а не строк. Переключение `language` меняет
строки, а шрифт следует за ним сам; в `MENUDEF` нет ничего, что зависело бы
от языка.

**Где он используется — список исключений.** D22 сохраняет латиницу для
имён собственных, калибров и подсказок клавиш. `SDMENU` называют только три
описателя меню выше (главное, сложности и, с D41, эпизода), и только для
строк, в которых ничего из этого нет; сами названия эпизодов рисуются в
`SmallFont`; `BigFont` и
`SmallFont` (названия уровней, метки оружия, подбираемые предметы, названия
сложностей) не затрагиваются. Любой новый `Font "SDMENU"` в другом месте
сначала должен пройти эту проверку.

Правила, которым следуют строки (`tests/test_menudef.py`):

- Строки `SD_MNU_*` пишутся **заглавными**. В шрифте нет строчных глифов, а
  рисует ли GZDoom строчные заглавными глифами шрифта из папки, где есть
  только заглавные, для этого шрифта **НЕ ПРОВЕРЕНО** (именно это явно
  делает `SmallFont` с названиями сложностей). Заглавные снимают вопрос.
  Принимает ли шрифт, состоящий только из наших полноцветных PNG,
  трансляцию `Cream` / `Gold` так, как `SmallFont` принимает `Gold`, тоже
  **НЕ ПРОВЕРЕНО** до прогона в движке.
- У каждого символа каждой строки `SD_MNU_*`, в обоих языках, есть глиф в
  `assets/fonts/sdmenu/`.
- Каждый пункт главного меню помещается правее x = 97, а заголовок —
  правее x = 32, измеряя как сумму ширин PNG глифов (самые широкие сегодня:
  «НОВАЯ ИГРА», 117 px; «ВЫБЕРИТЕ СЛОЖНОСТЬ», 222 px).
- `tools/check_pk3.py` (категория `menus`) отклоняет пакет, когда `MENUDEF`
  называет шрифт, который не является ни шрифтом движка, ни папкой
  `fonts/<name>/` в PK3.

Два поведения движка, которые заменили бы шрифт, оба прочитаны в
`gzdoom.pk3` (g4.14.2):

- `ui_generic` (`generic_ui` в ZScript): когда игрок включает его, list-меню
  рисуют текст шрифтом `NewSmallFont` вместо нашего
  (`zscript/engine/ui/menu/listmenuitems.zs`, строки 130 и 180,
  `menucustomize.zs`, строка 27). Это выбор игрока в пользу доступности, и
  мы его не трогаем.
- `MainMenuTextOnly`: движок поставляет второе, чисто текстовое главное
  меню, «чтобы использовать с локализованным содержимым» (`menudef.txt`,
  строки 108–138), и исполняемый файл содержит это имя. Когда движок
  переключается на него, **НЕ ПРОВЕРЕНО**. Свидетельство, что для нас он
  этого не делает: русское главное меню в
  `docs/qa/evidence/2026-10-13_1007_F2_mainmenu-ru.png` нарисовало НАШЕ
  переобъявленное `MainMenu` (логотип в 60,0). Если русский снимок D31
  когда-нибудь покажет строки движка с логотипом в 94,2, переобъявите
  `MainMenuTextOnly` с тем же телом.

ZScript здесь не задействован вообще. Мод может писать в CVar из ZScript
только пока движок обрабатывает ввод меню — `DMenu::InMenu` поднимается
вокруг `OnUIEvent`, `OnInputEvent` и `MenuEvent` и ни вокруг чего больше
(gzdoom: src/common/menu/menu.cpp, исходник движка, не файл этого репозитория), — так что запись из `Init`, `Ticker` или
`Drawer` аварийно завершает VM и выбрасывает игрока в консоль. **Не
добавляйте класс ZScript для меню, который пишет в CVar.**

Четыре переобъявленных меню — копии собственных тел GZDoom 4.14.2: якорь
`os_Menu` буквально, `MainMenu` со сдвинутым логотипом и пунктами, ставшими
текстом, `SkillMenu` и (D41) `EpisodeMenu` с новой раскладкой, как описано
выше. Пересверяйте их с
`gzdoom.pk3/menudef.txt` при каждом обновлении движка (долг T14).

## 7. Команды

```sh
python3 tools/build.py                       # → dist/sovietdoom.pk3
python3 tools/build.py --print-textmap MAP01 # показать сгенерированный UDMF
python3 -m unittest discover -s tests -v     # тесты сборки
tools/run.sh                                 # сборка + gzdoom + logs/gzdoom.log
MAP=MAP02 tools/run.sh                       # тестовый полигон арсенала F4
MAP=MAP01 SKILL=4 IWAD=/path/doom2.wad tools/run.sh -nosound
tools/run.sh -nosound +vid_fullscreen 0 +screenshot_dir "$PWD/logs/shots" +"wait 140; screenshot; wait 35; quit"  # доказательства QA
python3 tools/smoke.py --map MAP01 --skill 4 [--keep-evidence]  # сборка + самозавершающийся запуск GZDoom + разбор лога (код 0 = чисто)
python3 tools/check_pk3.py [--json] [--strict]   # статическая проверка PK3 без движка: лампы, WAD-файлы карт, используемые текстуры, палитра PNG, спрайты, лицензии, #include, шрифты, названные в MENUDEF (код 0 = чисто)
```

`run.sh` ищет GZDoom в `/Applications/GZDoom.app/Contents/MacOS/gzdoom`,
`~/Applications/…`, в Windows — `%LOCALAPPDATA%\Programs\GZDoom\gzdoom.exe`
и `%ProgramFiles%\GZDoom\gzdoom.exe` (в том же порядке, что `smoke.py` и
`audition.py`), и в `PATH` (или `GZDOOM=`); IWAD — в `iwads/`,
`~/Library/Application Support/gzdoom/` и `$DOOMWADDIR` (или `IWAD=`),
предпочитая `freedoom2.wad`. Он отказывается запускать движок, если не
задан `SD_ALLOW_ENGINE=1` (гейт движка, `docs/PIPELINE.md`, этап 5).
Всегда пишет `logs/gzdoom.log`; `qa-engineer` ищет в нём `Script error`,
`Unknown texture`, `Missing sprite`: любое совпадение — провал. В Windows
команды выше работают так же под Git Bash с `python` вместо `python3`;
`run.sh` сам выбирает интерпретатор из venv. Скриншоты в обеих системах
берутся командой `screenshot` движка (`screencapture` в macOS не видит
окно игры).

## 8. Инструменты для арта

Виртуальное окружение Python в `.venv/` (в gitignore) с Pillow и numpy для
`tools/art/`. Создание: `python3 -m venv .venv && .venv/bin/pip install pillow numpy`.

## 9. Баланс

Каждое игровое число арсенала и причина, по которой оно такое, живёт в
`docs/engine/BALANCE.md`. Этот файл владеет *именами и структурой*; тот —
*значениями*. Код владеет и тем, и другим как именованные константы — если
документ и код расходятся, прав код, а документ — ошибка.
