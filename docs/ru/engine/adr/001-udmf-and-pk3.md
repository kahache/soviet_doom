# ADR 001 — UDMF + PK3 + карты, генерируемые скриптом

Дата: 2026-10-09. Статус: принято (F0), проверено на гейте G0. Владелец:
`mod-engineer`. Каноническая версия: `docs/engine/adr/001-udmf-and-pk3.md`.

## Контекст

Полный пайплайн (исходники → пакет → GZDoom загружает играбельную карту) нужно
было проверить до появления текстур, настоящих карт и решений CEO о названии,
IWAD и версии движка. Ограничения машины: Intel Mac, macOS 12.7, Python 3.14
только со стандартной библиотекой, без Ultimate Doom Builder и SLADE.

Три связанных решения: формат пакета, формат карты и способ создания карт.

## Варианты

**Пакет: единый WAD или PK3.** Единому WAD нужны маркеры (`S_START`/`S_END`,
`F_START`…), имена ≤ 8 символов везде и сборщик (SLADE или более сложный
писатель). PK3 — zip с осмысленными папками, монтируется GZDoom напрямую,
создаётся стандартным `zipfile` и просматривается через `unzip -l`.

**Карта: бинарный формат Doom или UDMF.** Бинарному нужны упакованные структуры
по лампам и BSP-ноды; UDMF (`TEXTMAP`) — читаемый текст `key = value;`,
расширяемый (пространство имён `zdoom`), пригодный для diff в git, а ноды
GZDoom строит при загрузке.

**Создание карт: редактор (UDB) или скрипт.** UDB — стандарт, но без нативной
сборки для macOS 12 (НЕ ПРОВЕРЕНО, работает ли там свежая версия); скрипт на
Python воспроизводим и рецензируем, но ограничен для сложной ручной геометрии.

## Решение

1. **PK3**, генерируемый `tools/build.py` из `src/`, детерминированно. Ничего не
   кладётся в пакет вручную.
2. **UDMF, пространство имён `zdoom`** для всех карт; без лампов нод.
3. Карты могут быть **сгенерированы скриптом** (`src/maps/<MAP>/map.py` с
   `tools/sdbuild/udmf.py`) **или сданы как `.wad`** от `level-designer`
   (`src/maps/<MAP>.wad`); сборка принимает оба варианта.
4. Минимальный собственный писатель WAD (`tools/sdbuild/wad.py`), потому что
   каждая карта внутри PK3 живёт в своём WAD, и мы не хотим зависеть от SLADE.
5. `tools/run.sh` собирает перед запуском (если не `SD_NO_BUILD=1`), чтобы
   «то, что запускается» всегда было «тем, что лежит в `src/`».

## Последствия

- Положительные: весь пайплайн умещается в стандартную библиотеку;
  побайтово идентичные сборки; `TEXTMAP` читается в diff PR; добавить карту —
  значит добавить папку или `.wad`.
- Долг: без визуального редактора геометрию диктует Python (оценить UDB на
  Windows-ПК); `udmf.py` моделирует только используемые поля и будет расти с
  дверями, действиями и тегами, со своими тестами; писатель WAD — не
  универсальный редактор.
- Здесь не решается: название мода, базовый IWAD, минимальная версия GZDoom (D1–D3).

## Проверка (выполнена на G0, 2026-10-09)

Все пункты проверены на GZDoom 4.14.2 + freedoom2.wad 0.13.0:
`maps/MAP01.wad` только с маркером/TEXTMAP/ENDMAP загружается, ноды строятся
без сообщений; ориентация linedef (по часовой, y вверх) направляет передний
sidedef внутрь (без HOM); `music = ""` даёт тишину без предупреждения;
`STARTAN2`, `FLOOR4_8`, `CEIL3_5`, `SKY1` есть в Freedoom; `AddEventHandlers`
работает, обработчик печатает свою строку. Одна поправка: `lookup` недопустим
внутри блока `episode`; используйте `name = "$ID"`.
