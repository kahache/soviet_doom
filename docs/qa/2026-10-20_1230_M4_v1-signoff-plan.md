# M4 / G6 — the v1.0 sign-off plan

Dated snapshot (2026-10-20 12:30), owner `qa-engineer`. The ordered checklist
the PM runs in GZDoom on the release candidate, so the sign-off can start the
moment the last installs land. Gate and package contract:
`docs/engine/RELEASE.md` (§1 the zip, §2 rows 1-7); milestone: `docs/ROADMAP.md`
M4. After the run, `qa-engineer` writes the G6 entry in
`docs/qa/GATE-REVIEWS.md` from the evidence this plan names.

Nothing here was run in the engine (D26). §8 records the clean-clone dry run
made today without the engine.

## 0. How to read this plan

- **[AFTER INSTALL: Dxx]** marks an item whose content is still being
  installed on 2026-10-20. It is run like the others, but it cannot PASS
  before that install is committed. Today: player effects (D82, M2c-i),
  enemy sounds and the 7 voice takes (D83, D86, D91; N9e/N9), the HUD
  (status bar A, the Gemini face, N2 digits: D89, D90, D92; M2e), MAP01's
  new piece (D92), the range's D_SDM01T (D86) and the intermission's
  D_SDTITL (D83), the stats/help screens and quit lines (M2e, D75), the
  technology/AI credit (D93, G11), the Russian review (N11).
- **PASS** is what the screen, the speaker or the file must show. Anything
  else is a FAIL, filed as a numbered bug (`QA-M4-n`) with repro,
  expected/observed, severity and owner, and the run continues.
- **Evidence** goes to `docs/qa/evidence/` as
  `2026-MM-DD_HHMM_M4_signoff-<item>.png|.log`, plus one evidence note
  `…_M4_signoff-run.md` listing every item id, verdict and file. Screenshots
  with the engine's `screenshot` console command and
  `+screenshot_dir <evidence dir>`; logs with `+logfile <file>`.
- **Console** (`~`). Single-player cheats used below (`god`, `buddha`,
  `notarget`, `freeze`, `give`, `summon`, `kill`, `map`) are GZDoom's
  standard ones. Item ids (S1, W3, …) are stable: the G6 entry cites them.
- Order matters: §1-§2 are done once, before anything else touches the
  config; §3 automates what can be; §4-§6 are by hand; §7 closes.
