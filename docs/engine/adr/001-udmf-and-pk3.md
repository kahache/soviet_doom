# ADR 001 — UDMF + PK3 + script-generated maps

Date: 2026-10-09. Status: accepted (F0), verified at gate G0. Owner:
`mod-engineer`. Russian mirror: `docs/ru/engine/adr/001-udmf-and-pk3.md`.

## Context

The full pipeline (sources → package → GZDoom loads a playable map) had to be
validated before having textures, real maps or CEO decisions on name, IWAD
and engine version. Machine constraints: Intel Mac, macOS 12.7, Python 3.14
stdlib only, no Ultimate Doom Builder or SLADE.

Three coupled decisions: package format, map format, and how maps are made.

## Options

**Package: single WAD vs PK3.** A single WAD needs markers
(`S_START`/`S_END`, `F_START`…), ≤ 8-character names everywhere and an
assembler (SLADE or a more complex writer). A PK3 is a zip with meaningful
folders, mounted directly by GZDoom, produced by stdlib `zipfile`, and
inspectable with `unzip -l`.

**Map: binary Doom format vs UDMF.** Binary needs packed structs per lump and
BSP nodes; UDMF (`TEXTMAP`) is readable `key = value;` text, extensible
(namespace `zdoom`), diffable in git, and GZDoom builds nodes at load.

**Map production: editor (UDB) vs script.** UDB is the standard but has no
native build for macOS 12 (NOT VERIFIED whether a recent version runs there);
a Python script is reproducible and reviewable, but limited for complex
hand-made geometry.

## Decision

1. **PK3** generated by `tools/build.py` from `src/`, deterministic. Nothing
   is put into the package by hand.
2. **UDMF, namespace `zdoom`** for all maps; no node lumps.
3. Maps may be **script-generated** (`src/maps/<MAP>/map.py` using
   `tools/sdbuild/udmf.py`) **or delivered as `.wad`** by `level-designer`
   (`src/maps/<MAP>.wad`); the build accepts both.
4. Minimal own WAD writer (`tools/sdbuild/wad.py`) because every map inside a
   PK3 lives in its own WAD and we do not want to depend on SLADE.
5. `tools/run.sh` builds before launching (unless `SD_NO_BUILD=1`) so that
   "what runs" is always "what is in `src/`".

## Consequences

- Positive: the whole pipeline fits in stdlib; byte-identical builds; the
  `TEXTMAP` is readable in a PR diff; adding a map is adding a folder or a
  `.wad`.
- Debt: without a visual editor geometry is dictated by Python (evaluate UDB
  on the Windows PC); `udmf.py` models only the fields we use and will grow
  with doors, actions and tags, with its own tests; the WAD writer is not a
  general editor.
- Not decided here: mod name, base IWAD, minimum GZDoom version (D1–D3).

## Verification (done at G0, 2026-10-09)

All items verified on GZDoom 4.14.2 + freedoom2.wad 0.13.0:
`maps/MAP01.wad` with only marker/TEXTMAP/ENDMAP loads and nodes are built
silently; linedef orientation (clockwise, y up) puts the front sidedef inward
(no HOM); `music = ""` is silent without warning; `STARTAN2`, `FLOOR4_8`,
`CEIL3_5`, `SKY1` exist in Freedoom; `AddEventHandlers` works and the handler
prints its line. One correction: `lookup` is not valid inside an `episode`
block; use `name = "$ID"`.
